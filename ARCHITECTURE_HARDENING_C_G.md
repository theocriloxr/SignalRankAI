# SignalRankAI Architecture Hardening Blueprint (Packages C-G)

**Date**: 2026-09-30
**Status**: DRAFT (Baseline for Implementation)
**Scope**: Work Packages C through G

This document serves as the implementation directive for the remaining work packages defined in the `SignalRank_Master_Blueprint_2026.md`.

## WORK PACKAGE C — SIGNAL-STARVATION / ML / DATA

1. **Persisted Rejection Funnel & Metrics**
   - *Current State*: `ml_rejected_signals` table exists. `admin_pulse.py` tracks rejection metrics.
   - *Hardening Required*: Ensure `decision_log` table accurately tracks dropped signals across all layers (API, Engine, ML). Unify `admin_pulse` and `ml_rejected_signals`.

2. **Audit training-serving feature parity**
   - *Hardening Required*: Implement a feature schema hash that is signed during ML training. Serving must verify this hash before feature inference.

3. **Split drift diagnostics & Segment Calibration**
   - *Hardening Required*: Split `ml_drift_thresholds` into independent dimensions (Crypto vs FX, 1h vs 4h). Track calibration error independently per market segment.

4. **Challenger candidate-only gates**
   - *Hardening Required*: Introduce `challenger_mode=True` flag in ML runtime. Models in this mode write to a shadow outcome table (`ml_shadow_outcomes`) instead of gating real signals.

5. **Provider SLAs and Gap Checks**
   - *Hardening Required*: Integrate `yfinance` market calendar awareness. If a signal arrives outside of normal trading hours, bucket it into a `market_closed` gap queue instead of rejecting it as stale.

## WORK PACKAGE D — WEBSITE / PRODUCT EXPERIENCE

1. **Replacement Frontend**
   - *Current State*: Existing monolithic frontend.
   - *Hardening Required*: Spin up a dedicated `web/` Next.js or React application. Implement strict typed interfaces matching `openapi.json` generated by FastAPI.

## WORK PACKAGE E — PAPER / BROKER / RISK

1. **Transactional Paper Accounting**
   - *Current State*: Uses `RuntimeState`.
   - *Hardening Required*: Migrate to `paper_ledger.py` with immutable, double-entry transactional accounting for paper trades, identical to real execution structure.

## WORK PACKAGE F — ARCHITECTURE CLEANUP

1. **Split Oversized Modules**
   - *Hardening Required*: Break down `railway_main.py` (160k bytes) and `config.py` into domain-specific modules (`engine_runner.py`, `web_runner.py`, `worker_runner.py`).

## WORK PACKAGE G — OBSERVABILITY AND SECURITY

1. **Structured JSON logs with correlation IDs**
   - *Hardening Required*: Replace `logging.getLogger` with structured logging (e.g., `structlog`).
   - *Implementation*: Inject a `correlation_id` via middleware on every incoming request or signal stream. Attach it to all outbound DB/Redis/Discord operations.
