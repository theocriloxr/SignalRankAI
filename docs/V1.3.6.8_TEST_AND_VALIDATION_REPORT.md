## Full-suite limitation in this sandbox

The complete repository suite cannot finish collection because this execution environment does not contain the project's runtime packages `python-telegram-bot` and `APScheduler`. Seven test modules fail during collection for that reason. An additional broad run that excluded those seven collection-blocked modules reached **402 passed, 1 skipped** before stopping at 20 failures; 18 of those failures were also direct imports of the same missing runtime dependencies.

One unrelated test remains genuinely failing:

```text
tests/test_deploy_log_regressions.py::test_admin_pulse_uses_db_evidence_when_global_stats_are_zero
```

It fails identically in the unmodified v1.3.6.7 package (`delivered` is `0`, expected `2`), so it is a pre-existing baseline defect rather than a v1.3.6.8 regression.

An order-sensitive provider-routing test failed in the broad shared-process run but passes when run alone in both v1.3.6.7 and v1.3.6.8. Treat that as test isolation/global-state debt and rerun the full suite in the project's normal dependency-complete CI image.

10. Telegram commands/buttons acknowledge promptly and webhook p95/p99 meet the configured SLOs;
11. all execution/copy/public-performance flags remain disabled.
