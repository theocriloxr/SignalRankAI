## Duplicate-credential consolidation already in place

The connector registry (`data/connector_registry.py::_PROVIDER_KEYS`) already
maps aliases to one canonical name per provider:

```text
twelvedata_connector: TWELVEDATA_API_KEY | TWELVE_DATA_API_KEY
oanda_connector:      OANDA_API_KEY | OANDA_TOKEN
alpaca_connector:     ALPACA_API_KEY | APCA_API_KEY_ID  (+ secret pair)
alphavantage_connector: ALPHAVANTAGE_API_KEY | ALPHA_VANTAGE_API_KEY
eodhd_connector:      EODHD_API_KEY | EODHD_API_TOKEN
```

Rule going forward: **one credential, one canonical variable, temporary
backward-compatible aliases with a deprecation warning** — never two variables
holding the same secret.
