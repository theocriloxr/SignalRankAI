You are continuing work on SignalRank after receiving:

1. the SignalRank 54-page Master Blueprint;
2. the Master Implementation Directive;

This directive is the FINAL HARDENING ADDENDUM.

Treat every requirement below as mandatory unless technically impossible or dependent on an external provider. Any exception must be documented with evidence.

The purpose of this phase is NOT to endlessly add features.

The purpose is to tighten the entire SignalRank platform until:

- behavior is deterministic where required;
- multi-user isolation is correct;
- trading-account isolation is correct;
- financial calculations are reliable;
- risk controls fail closed;
- production changes are traceable;
- external-provider failures are survivable;
- users cannot accidentally or maliciously cross security boundaries;
- live and prop execution cannot occur outside certified paths;
- system recovery is deterministic;
- every important claim has evidence;
- and the system can scale safely beyond the owner account.

Do not weaken existing safeguards.

Do not remove functionality solely to simplify implementation.

Do not mark a feature complete because code exists.

Do not mark SignalRank production-ready until certification evidence exists.

2. FAIL-CLOSED PRINCIPLE
======================================================================

SignalRank must default to safety.

When SignalRank cannot establish that an action is safe, valid and authorized, it must not trade.

Examples:

unknown account state
→ block execution;

stale market data
→ block execution;

broker reconciliation mismatch
→ block execution;

prop-rule uncertainty
→ block execution;

unknown instrument metadata
→ block execution;

invalid financial precision
→ block execution;

risk service unavailable
→ block execution;

database consistency problem
→ block execution;

execution state unknown
→ reconcile before further trading;

LLM unavailable
→ continue deterministic core behavior without AI;

notification failure
→ do not incorrectly alter trade state.

Create reusable fail-closed primitives instead of implementing ad-hoc checks in many places.
