Based on the SignalRank system we’ve already been building, I would treat the goal as turning it from a signal bot with a web interface into a multi-asset trading-intelligence platform with institutional-style research, validation, execution safety, personalization, observability, and continuous learning.
The most important point first: I would not optimize SignalRank around “70%+ win rate” alone. A strategy can win 75% of trades and still lose money if its losses are much larger than its wins. SignalRank should optimize a portfolio of metrics: expectancy, profit factor, risk-adjusted return, maximum drawdown, calibration, tail loss, slippage sensitivity, and then win rate.

The order I would actually implement all of this
I would divide the work into eight releases:
Release 1 — Make SignalRank unquestionably correct
Staging, DBs, migrations, release fingerprints, signal state machine, active-signal tracking, provider health, identity, tests and current bugs.
Release 2 — True multi-asset SignalRank
Crypto + FX + equities + stocks + indices + commodities routing, sessions, canonical assets, cross-asset provider architecture and coverage diagnostics.
Release 3 — Quant intelligence
Regime engine, strategy attribution, improved scoring, rejected-signal tracking, realistic backtester, shadow trading and calibration.
Release 4 — Learning system
Feature store, datasets, walk-forward training, model registry, champion/challenger, drift and degradation detection.
Release 5 — Risk and portfolio brain
Sizing, portfolio correlation, exposure, risk budgets, circuit breakers and kill switches.
Release 6 — Perfect product experience
Complete website/Telegram parity, redesigned dashboard, charts, analytics, replay, AI assistant and rich Telegram UX.
Release 7 — Execution
Paper → assisted → tightly controlled live execution, broker reconciliation, idempotent orders and multiple broker adapters.
Release 8 — Scale and commercial platform
APIs, webhooks, subscriptions, referrals, public evidence, native apps, status page, operations tooling and scaling.
The single biggest architectural change I recommend
Don't think of SignalRank as:
“A bot that generates good signals.”

Build it as:
“A continuously evaluated, multi-asset market-intelligence and risk system that searches thousands of opportunities, measures its own mistakes, learns from accepted and rejected decisions, explains its reasoning, personalizes opportunities to the user, and can safely carry a validated idea all the way from market data to execution and post-trade learning.”

If we build that, nearly every problem you've mentioned—crypto-heavy output, inconsistent signals, uncertain learning, lifecycle bugs, website/Telegram mismatches, reliability, execution safety and confidence quality—has a natural place in the architecture.
